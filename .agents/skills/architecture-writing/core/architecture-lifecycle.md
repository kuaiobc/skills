# Architecture Lifecycle

Architecture is maintained through:

`Discover → Baseline → Decide → Deliver → Observe → Learn → Change → Re-baseline`

Track architecture changes as first-class events. A changed boundary, ownership model, data flow, deployment coupling, trust boundary, or integration pattern can invalidate earlier decisions even when application behavior appears unchanged.

Use supersession links for decisions and diagrams. Never silently rewrite historical decisions without preserving what changed and why.
