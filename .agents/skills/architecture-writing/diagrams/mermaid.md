# Mermaid Architecture Diagram Standard

Mermaid is the primary diagram representation for this Skill.

Rules:
- stable IDs and consistent naming;
- one architectural question per diagram;
- avoid crossing lines where possible;
- keep labels concise;
- distinguish sync calls, async events, data flow, and trust boundaries;
- keep abstraction levels consistent;
- never introduce a component in a diagram that is absent from the model;
- diagram source should be reviewable as code.

Required QA: semantic consistency, scope consistency, directionality, relationship correctness, naming consistency, and readability.
