# Requirement Analysis

Separate requirements into business, functional, quality, operational, regulatory, integration, data, and evolution concerns.

For each requirement capture:
- ID
- statement
- source/stakeholder
- priority
- acceptance measure
- scope
- dependencies
- confidence
- architecture implication

### Requirement transformation

`Need → Requirement → Scenario → Measure → Architecture Driver`

Avoid converting vague preferences directly into technology choices. Example: “must be fast” becomes a measurable latency scenario before architecture selection.
