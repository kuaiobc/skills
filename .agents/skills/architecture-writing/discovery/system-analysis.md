# System Analysis

Analyze the system from four complementary views:

1. **Structure** — components, modules, dependencies.
2. **Behavior** — request, event, batch, failure flows.
3. **Data** — ownership, lifecycle, consistency, movement.
4. **Runtime** — deployment, scaling, failure domains, observability, security boundaries.

Use multiple views because a clean static dependency graph can hide runtime coupling or data ownership problems.
